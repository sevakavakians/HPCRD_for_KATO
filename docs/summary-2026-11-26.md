# HPCRD for KATO: what was done, and how well it works

26 Nov 2026. A summary for a reader who was not involved in the work. The detailed notes are listed at the end. Earlier messages and the notes call the four steps below "rounds". Added later the same day: a follow-up on test B, one line on Drain under test A, and one corrected count (223 is 224; section 4 says where).

**In brief.** KATO can build rules with variables from raw sequences and edit them as data arrives, using only its existing API. On log files this scores 0.81 on a published benchmark: level with the published method it implements (0.79), below the best one (0.87). On natural-language sentences it is poor: at best 22% of the marked values are found exactly.

## 1. The question

Can KATO, given raw sequences, work out their structure by itself? Three things were asked for:

1. **Segment**: split a sequence into its parts without being told where the parts are.
2. **Chunk**: store a stretch that keeps coming back as one unit.
3. **Make rules**: turn sequences that differ in a few places into one pattern with a **variable** at each of those places.

An example, from a real run. Three sentences arrive, one after another:

```
book for two at seven .
book for six at seven .
book for six at nine .
```

After the third, KATO holds one live **rule**, `[book for] [VAR|1] [at] [VAR|2] [.]`, the **chunk** `book for` that the rule uses, and the values seen at each variable: `two` and `six` for `VAR|1`, `seven` and `nine` for `VAR|2`. The two earlier versions of the rule are still stored, retired.

HPCRD stands for hierarchical pattern chunking and rule discovery. The data so far is text, one word per KATO event.

## 2. The method, in short

A small module sits on top of KATO and uses only KATO's existing API. Nothing in KATO was changed.

1. Each new sequence is shown to a KATO node that holds the rules learned so far.
2. KATO's prediction says which parts of the sequence match a known rule and which do not.
3. The parts that match stay as they are. Each stretch that does not match becomes a variable. A run of matching words that recurs is stored as a chunk.
4. When a new sequence changes a rule, the module teaches KATO the new version and **retires** the old one. So a rule is edited as data arrives, and every earlier version stays stored.

## 4. How well it works

There are two tests. They ask different questions, and a number from one cannot be compared with a number from the other.

### Test A: log files, against published results

**What it is.** A public benchmark for this very task (Zhu et al. 2019): 16 software systems, 2,000 log lines from each, sorted by hand into message types. A method reads the lines and groups them by the rule each line fits.

**The score.** Accuracy is the share of lines whose group is exactly the group made by hand. 1.000 is perfect. It is strict: one line in the wrong group makes every line of that group count as wrong.

**Why logs.** This is the one place I found where "find rules with variables" has published scores, so the code can be checked against numbers we did not produce. It was a check of the implementation. It was not expected to beat anything.

| System | KATO, this work | Spell, published | Drain, published |
|---|---|---|---|
| Apache | 1.000 | 1.000 | 1.000 |
| HDFS | 0.998 | 1.000 | 0.998 |
| Windows | 0.989 | 0.989 | 0.997 |
| Zookeeper | 0.964 | 0.964 | 0.967 |
| Android | 0.908 | 0.919 | 0.911 |
| Spark | 0.905 | 0.905 | 0.920 |
| HPC | 0.904 | 0.654 | 0.887 |
| Thunderbird | 0.847 | 0.844 | 0.955 |
| BGL | 0.797 | 0.787 | 0.963 |
| Hadoop | 0.777 | 0.778 | 0.948 |
| OpenStack | 0.764 | 0.764 | 0.733 |
| HealthApp | 0.760 | 0.639 | 0.780 |
| Mac | 0.749 | 0.757 | 0.787 |
| Linux | 0.605 | 0.605 | 0.690 |
| Proxifier | 0.526 | 0.527 | 0.527 |
| OpenSSH | 0.484 | 0.554 | 0.788 |
| **Average of the 16** | **0.811** | **0.793** | **0.866** |

Spell is the published method that the module implements. Drain is the best-scoring method of that study. Both columns are the study's own figures.

**How to read it.**

1. **0.811 means** that on average 81 of 100 log lines are grouped exactly as people grouped them.
2. **Verdict: adequate, and as expected.** It is level with the method it implements (0.793) and about 5 points under the best-scoring method of that study (0.866).
3. **It varies a lot by system**, from perfect or nearly so (Apache 1.000, HDFS 0.998) to poor (OpenSSH 0.484, Proxifier 0.526). Published Spell varies the same way.
4. **The check passed.** Line by line, KATO groups all 32,000 lines as the algorithm in Spell's paper does, with one known exception: a log line of a single word, which KATO does not learn as a pattern. That exception is why HPC reads 0.904 against 0.654, and it is not a sign of a better method. Without HPC the average is 0.805, the same as for the paper's algorithm.
5. Where other numbers differ from published Spell, most visibly HealthApp and OpenSSH, the cause is in the benchmark's own program, which adds two shortcuts to the algorithm. The note for step 4 has the evidence.
6. **Drain's way of grouping runs on KATO too** (added 26 Nov). With it, KATO scores 0.865 on average, where the published figure for Drain is 0.866, and equals the published figure on each of the 16 systems after rounding. `entropy-and-rule-units-2026-11-26.md`, section 7.

### Test B: dialogue sentences

**What it is.** 3,873 user sentences from 384 dialogues of Google's Schema-Guided Dialogue data set. In most of them a user asks an assistant to find or book a restaurant; in the rest, to find a film. The data set marks 1,388 **slots** in these sentences: the spans that carry a value, namely a time, a city, a kind of food, a date, a restaurant's name or a film's title. Those are what a good rule should turn into variables.

**The score.** The share of the 1,388 slots that are exactly one variable, same first and last word, in the rule made for the sentence at the moment it arrived. 100% would be perfect.

**No published yardstick.** I found no published scores for a method of this kind on this data. For comparison, two published log parsers were run on the same sentences.

| Method | Slots found exactly, of 1,388 | Variables it marked | Of those, exactly a slot |
|---|---|---|---|
| Drain, a published log parser | 150 (10.8%) | 6,264 | 2.4% |
| Spell, a published log parser | 224 (16.1%) | 4,011 | 5.6% |
| KATO, step 2: compare with the nearest earlier sentences | 222 (16.0%) | 2,715 | 8.2% |
| KATO, step 2, best setting: also read the known rules first, and look inside each variable | **300 (21.6%)** | 4,404 | 6.8% |
| KATO, step 4: Spell's procedure on KATO | 216 (15.6%) | 4,047 | 5.3% |
| KATO, step 4, and look inside each variable | 250 (18.0%) | 4,159 | 6.0% |

Drain was run through the `drain3` package. Spell was written from its paper's description and checked on test A. Its row first read 223 and 4,003: the sentences that joined the very first rule had been scored as having no rule. The percentages did not change.

**How to read it.**

1. **Verdict: poor.** The best setting finds about one slot in five exactly.
2. **Most of what it marks is not a slot.** Between 5% and 8% of its variables are exactly a slot. The data set marks those six kinds of value only, so this understates the method. It still shows that it marks far more than slots.
3. **The published parsers do no better here** (11% and 16%). The weakness is in this kind of method, not in how it was built on KATO.
4. **Why.** These methods make one rule for a whole sentence. That fits a log line, which is one message. A sentence with a slot is more often several pieces put together: what is wanted, where, when, for how many. With the published procedure, 48% of the slots are in a sentence that fits no existing rule well enough when it arrives. Changing the threshold does not help: no value got past 16.4%.
5. **The original design**, rolling windows of 7 words, was measured on the first 1,200 sentences: 17.8% of their slots, against 17.5% for the best whole-sentence setting, and 158 seconds against 14.

### A follow-up on test B: can entropy help? (26 Nov)

The question was whether entropy could keep a rule from being one rule for a whole sentence. Four things were measured on the same sentences. The detail, and what others have published on the problem, is in `entropy-and-rule-units-2026-11-26.md`.

| What was tried | Slots found exactly, of 1,388 | Verdict |
|---|---|---|
| One rule per sentence, as above: Spell's procedure on KATO | 216 (15.6%) | The starting point. |
| The same, and a sentence may join a rule only if the rule explains it better than chance, by KATO's own measure | 161 (11.6%) | Worse. The measure counts a slot's value as noise. |
| Cut each sentence where what comes next is uncertain, and count the slots that are exactly one piece | 644 (46.4%); cuts placed at random give 19% | Works, as a way to cut. A piece is not yet a variable. |
| One rule per sentence again, made from those pieces | 260 (18.7%) | No real gain. |
| The smallest rule for a part of a sentence: two words with a piece between them | 344 to 582 (24.8% to 41.9%), marking 1.3 to 3 times as many variables | Finds more. Not selective. |

**How to read it.** Entropy says well where a value begins and ends, and KATO already returns the distribution it is taken from. It does not help as a test of whether a sentence fits a rule. The gain comes when a rule covers a part of a sentence. What is still missing is a way to decide which variables are worth keeping, and the published answer to that is to count the length of the whole description.

### Also checked: it runs on KATO itself

Most runs use a stand-in that calls KATO's own matching classes inside one Python process, which is 70 to 200 times faster than going through KATO's REST API. To make sure the stand-in tells the truth, parts of both tests were repeated through a live KATO service (v7.1.0 plus 34 commits, `f32bac0`): 19 tests, two of the 16 log systems, and the first 300 dialogue sentences. The results were the same, pattern for pattern.

Two faults in KATO's API turned up on the way. They are written up for the KATO repository in `docs/maintenance/retired-pattern-api-issues.md`.

## 5. The bottom line

1. **The mechanism works.** With its existing API (matching, learn, retire and un-retire), KATO builds rules with variables and edits them as data arrives. Every version of a rule stays stored and can be traced.
2. **On logs, where one sequence is one message, the quality is that of a published method**: 0.81 on a benchmark where that method has 0.79 and the best has 0.87.
3. **On natural language the quality is poor**: at best 22% of the annotated values. The limit is the unit, one rule for a whole sentence, and not a setting.
4. **Against the three goals.** Chunking and rule-making are built, and the two tests measure the rules. Segmenting is done inside a sequence, where the method finds the constant parts and the variable parts. The ends of the sequences themselves (sentence ends, line ends) were given to it. Rules made of smaller rules are not built.
5. **Next, proposed and not started:** rules for parts of sentences, with the length of the whole description as the judge of every edit (Bayesian model merging, Stolcke and Omohundro 1994), held to that paper's own test; and ADIOS (Solan et al. 2005) run as published on test B for a reference number. This replaces the earlier proposal to build ADIOS itself: its procedure needs the whole data at once and cannot undo a step.
6. **Decided on 26 Nov:** Spell's procedure is to be built as a KATO module, for data in which one sequence is one message. `methods-register.md` lists every method looked at and where it stands.

## 6. Words used

| Word | Meaning here |
|---|---|
| Node | One KATO instance with its own learned patterns. |
| Pattern | A sequence KATO has learned. Its name is a hash of its content. |
| Chunk | A run of words that recurs, stored as one pattern. |
| Rule, or template | A pattern made of constants and variables. |
| Variable (VAR) | A place in a rule where sequences differ. Its values are stored separately. |
| Slot | A span that the dialogue data set marks as carrying a value. Used only to score test B. |
| Threshold (tau) | How much of a sequence must match a rule for the sequence to join that rule. 0.5 unless stated. |
| Retire | KATO's way to hide a pattern without deleting it. Used here to replace an old version of a rule. |
